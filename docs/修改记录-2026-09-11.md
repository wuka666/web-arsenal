## 一、P0 · 功能修复

### 1. 18 套方案 demo 调参把布局写坏（54 个控件）

**问题**：demo 的消息监听把参数值裸写进 `setProperty('--'+key, value)`，而 `:root` 里
`--yuanjiao / --jianju / --zihao` 是带单位的（如 `14px`）。调参后变成 `--yuanjiao: 40`（无单位），
`border-radius: var(--yuanjiao)` 失效 → 圆角塌成 0、标题字号塌回 16px、内边距归零。

**改法**：18 个 demo 的监听行统一换成带单位白名单（18 个文件的这一行原本完全相同）：

```js
addEventListener('message', e => {
  const d = e.data; if (!d || d.type !== 'param') return;
  const U = { yuanjiao: 'px', jianju: 'px', zihao: 'px' };
  document.documentElement.style.setProperty('--' + d.key, d.value + (U[d.key] || ''));
});
```

**涉及文件**：`assets/demos/方案-{大色块分区,图片卡片流,玻璃拟态风,高密度卡片墙,杂志排版风,深色压顶风,暖调留白型,强对比视觉型,冷调科技型,自然有机型,复古胶片型,中式水墨型,双按钮,视觉重量,首页动线,动效节奏,整站首屏探索,焦点型Hero}.html`
+ `data/方案.js` 对应 18 处 `代码` 字段（两边用同一次替换，天然保持同步）。

**验证**（真实 Chrome，调 `yuanjiao=40 / jianju=40 / zihao=30` 后读计算样式）：

| | 改前（坏） | 改后 |
|---|---|---|
| `--yuanjiao` | `40`（无单位） | `40px` |
| 按钮圆角 | `0px` | `40px` |
| `h1` 字号 | `16px` | `78px` |

18/18 全部通过；`node --check data/方案.js` 通过；方案 `代码 ↔ 演示页` 同步 20/20。

> 注：`yinying` / `faguang` 两个参数在 CSS 里走 `calc(var(--x)*1px)`，本来就没问题，**不需要**补单位。
> 白名单是先用脚本扫描「默认值为数字 + `:root` 声明带单位 + 监听裸写」三个条件算出来的，确认只有那 3 个键。

### 2. 「生成方案」静默丢弃 34/92 条素材

**问题**：`index.html` 的 `buildPlanPrompt()` 分组字典键是 `{字体,颜色,版面,动效,留白}`，
而素材 `元素` 的实际取值是 `{视觉,动效,构成,反馈,布局,3D·粒子}`，两者只有「动效」一个交集。
结果 4 个分组恒为 0，**34 条素材被静默丢弃**（勾了 3 条可能一条都不出现）。

**改法**：分组键改为真实取值，并加「其他」兜底组（防止以后新增元素取值时再次静默丢失）：

```js
const groups = { "视觉": [], "动效": [], "构成": [], "反馈": [], "布局": [], "3D·粒子": [], "其他": [] };
chosen.forEach(it => {
  const hit = (it.元素 || []).filter(e => groups[e]);
  if (!hit.length) groups["其他"].push(it);   // 兜底
  hit.forEach(e => groups[e].push(it));
});
```

**验证**：抽取 `index.html` 里的真实函数源码，在 Chrome 里跑 `buildPlanPrompt()`，
用改前会被丢弃的 6 条（`s204`/`v108`/`v113`/`v132`/`v133`/`w001`）测试 → **6/6 全部出现在生成的提示词里**。
